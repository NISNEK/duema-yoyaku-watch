# デュエマ予約ウォッチ

デュエル・マスターズの**新しい予約ページが公開された瞬間**と**予約受付の開始**を見張り、スマホ（ntfy）と Discord にすぐ通知するツールです。
GitHub Actions（GitHub の自動実行サービス）で約5分おきに動き、自分のサーバーやパソコンを動かし続ける必要はありません。**費用は0円**です。

> はじめて設定する方は **[SETUP.md（設定手順書）](SETUP.md)** を上から順番に進めてください。

---

## できること

| 通知 | いつ届くか |
|---|---|
| 👀 予約ページ公開！ | ショップの一覧に、これまでなかったデュエマ商品が現れた時 |
| 🔔 予約開始！ | 商品が「受付前」から「受付中」になった時（公開時点で受付中ならこれだけ） |
| 🔁 再販開始！ | 一度買えた商品が、売り切れのあと再び買えるようになった時（オフにもできます） |
| ⚠️ 監視に失敗しています | 同じショップで3回続けて確認に失敗した時（1回だけ） |
| ⚠️ 見張りプログラムが止まっています | 設定ファイルの書き間違いなどで全体が動けない時（1日1回まで） |

- 同じ商品について、同じ通知が二度届くことはありません。
- 一度に6件以上見つかった時は、1通にまとめて届きます。
- 受付状況は**一覧ページ**（GitHub Pages）でも確認できます。スマホ対応です。

## 見張っているショップ

| ショップ | 見ているページ | 間隔 |
|---|---|---|
| ホビーサーチ | 「デュエル・マスターズ」の検索結果（新しい順） | 5分 |
| フルアヘッド | 予約販売コーナー（新着順） | 5分 |
| マスターズスクウェア | デュエマ「予約ブースターBOX・新品商品」コーナー | 5分 |
| カードラボ | 「新作予約・新品商品」コーナー | 5分 |

一覧ページの各商品には「**メルカリで探す**」ボタンがあります（メルカリの検索結果を開くだけで、このツールがメルカリにアクセスすることはありません）。

### 見張っていないショップと理由
Amazon・楽天・あみあみ・セブンネット・カードラッシュ（規約でロボットによる取得を禁止）、ヨドバシ・ビックカメラ・タカラトミーモール・ジョーシン・イオンスタイルオンライン・トイザらス・エディオン・ドラゴンスター（プログラムからのアクセスを遮断）、駿河屋・遊々亭・アニメイト通販・ハピネット（GitHub からのアクセスを拒否）、メルカリ（データの取り出し口が robots.txt で禁止）などは見張りません。
遮断を回避する改造は、相手サイトに迷惑をかけるため行わないでください。

## シングル通知（トレキャット・アメニティードリーム）

Discord の `# シングル通知` チャンネルで `!登録 カード名` と書くと、そのカードが**新規入荷・再入荷**した時に、登録した人へ **DM** で知らせます。`!検索 カード名` で2店の値段と在庫も調べられます（返事まで5〜15分）。
- 一覧ページの「**シングル**」タブで、最近の入荷を見られます（誰が何を登録したかは載りません）
- 登録リストは**暗号化**してリポジトリに保存し、鍵は GitHub Secrets にだけ置きます
- 設定は `single_settings.yml`、使い方は Discord で `!ヘルプ`、設定手順は [SETUP.md](SETUP.md) の「シングル通知編」

## このツールの約束

1. **通知まで。**自動購入・自動予約・ログイン・ロボット確認（CAPTCHA）の回避はしません。
2. **相手サイトに迷惑をかけない。**利用規約と robots.txt を守り、1ショップにつき数分に1ページだけ見ます。ツール名を正直に名乗ってアクセスします。
3. **秘密を守る。**ntfy のトピック名と Discord の Webhook URL は GitHub Secrets にだけ保存し、コード・ログ・一覧ページには出しません。

## ファイルの説明

| ファイル | 役割 | 触る？ |
|---|---|---|
| `shops.yml` | 見張る設定（ショップ・対象商品・再販通知のオン/オフ） | **書き換えてOK** |
| `manual.yml` | 手動登録（人が見つけた予約ページ） | **書き換えてOK** |
| `monitor/manual.py` | 手動登録を一覧ページに載せる | 触らない |
| `tools/connection_test.py` | 接続テスト（GitHub から見られるか確認） | 触らない |
| `monitor/main.py` | 全体の司令塔 | 触らない |
| `monitor/fetcher.py` | ページを取ってくる（robots.txt の確認も） | 触らない |
| `monitor/page_parser.py` | 商品を取り出して受付状況を判定する | 触らない |
| `monitor/state.py` | 前回との違いを見つける・記録する | 触らない |
| `monitor/notifier.py` | ntfy・Discord に通知する | 触らない |
| `.github/workflows/monitor.yml` | 5分おきの自動実行の設定 | 触らない |
| `docs/index.html` | 一覧ページ | 触らない |
| `docs/status.json` | 記録ノート（自動で更新される） | 触らない |

## よくある操作（詳しくは [SETUP.md](SETUP.md) の「運用編」）

- **自動で見張れないショップ（Amazon・イオンなど）の予約ページを一覧に載せる**：`manual.yml` に、ショップ名・商品名・URL・状態を書き足す（書き方はファイルの中に例があります）。プログラムがそのショップを見に行くことはありません

- **再販通知をオフにする**：`shops.yml` の `include_restock: true` を `false` に書き換える
- **ショップを休ませる**：`shops.yml` のそのショップの `enabled: true` を `false` に書き換える
- **通知が届くか試す**：Actions タブ → 予約ページ監視 → Run workflow → `test-notify`
- **設定を変えた後に確認する**：Actions タブ → 予約ページ監視 → Run workflow → `dry-run`（通知は送らず、結果だけ表示）

## 注意

- GitHub が混んでいると、5分おきが10〜15分おきになることがあります。
- ショップのページの作りが変わると、見張りが失敗することがあります。その時は「⚠️ 監視に失敗しています」が届きます。
- 取りこぼしを完全になくすものではありません。大事な商品はショップのページも確認してください。
